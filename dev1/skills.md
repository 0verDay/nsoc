### 🧩 核心模块分析

#### 1. 地图系统（index.html + style.css）
- 布局：3 列 × 6 行的棋盘，分为上下两个 3×3 网格
  - 上半部分（row 0-2）：敌方半场
  - 下半部分（row 3-5）：己方半场
- 使用 CSS Grid 布局，格子自适应保持正方形

#### 2. 卡牌系统（test_card.js）
- 目前仅有 2 张测试卡牌：
  | 名称 | 费用 | 攻击 | 血量 | 类型 |
  |------|:----:|:----:|:----:|:---:|
  | blanket | 1 | 1 | 1 | 单位 |
  | pro | 2 | 2 | 2 | 单位 |
- 手牌通过 getRandomCard() 从卡池中随机抽取
- 手牌最少保持 5 张（MIN_HAND_SIZE = 5）

#### 3. 游戏逻辑（game.js）
- 费用系统：玩家每回合有 10 费（MAX_MANA = 10），回合结束补满
- 拖拽放置：支持 HTML5 原生拖拽 API，单位卡牌只能放置在己方半场（row 3-5）
- 回合制（endTurn() 函数）：
  1. 玩家棋子从上往下、从左往右依次行动
  2. 敌方棋子从下往上、从右往左依次行动
  3. 逻辑：有相邻敌人则攻击 → 在边界则攻击主堡 → 否则向前移动一格
- 战斗系统：双方同时受到对方攻击力的伤害，血量为 0 则移除
- 动画系统：使用 requestAnimationFrame + 线性插值实现棋子平滑移动

#### 4. 关卡配置（test_level_config.js）
- UNIT_CONFIG 数组定义初始单位配置
- 初始开局：敌方 3 个 blanket 占满 row 0，己方 1 个 blanket 在 row 5 col 1

### 🔄 游戏流程

```
[游戏开始]
    ↓
初始化：设置血量、放置初始单位、补充手牌
    ↓
[玩家回合]
    ↓ 拖拽手牌到棋盘 ↓
消耗费用 → 放置单位 → 补充手牌
    ↓ 点击"结束回合" ↓
[棋子自动行动]
    ↓ 玩家棋子先动 ↓
    有相邻敌人 → 攻击
    在 row 0    → 攻击敌方主堡
    否则        → 向前移动一格
    ↓ 敌方棋子后动（同理反方向） ↓
[回合结束，回到玩家回合]
```

### ⚠️ 当前版本特点与局限

| 方面 | 现状 |
|------|------|
| 卡牌种类 | 仅 2 种测试卡牌 |
| 英雄/技能 | 无英雄、无技能系统 |
| 棋子类型 | 仅"单位"类型，无效果/能力 |
| AI 智能 | 无 AI，敌方按固定规则自动行动 |
| 胜利条件 | 未实现，主堡血量降至 0 后无结束逻辑 |
| 费用机制 | 每回合固定补满 10 费 |
| 交互方式 | 仅支持拖拽放置，无点击选择等操作 |
| 视觉效果 | 基础 CSS，无特效/音效 |

### 💡 总结

这是一个早期开发阶段的卡牌战棋游戏，使用纯原生前端技术开发。目前完成了最基础的棋盘渲染、卡牌拖拽放置、棋子自动移动和战斗的核心循环。项目结构清晰，模块划分合理（数据配置与逻辑分离），但功能还处于原型阶段，后续可扩展的方向包括：更多卡牌种类、英雄/技能系统、AI 对手、胜利条件、音效特效等。
